Привет. Я бы строил такой плеер как единое кроссплатформенное приложение с модульными источниками, а не как набор отдельных интеграций с сайтами.

Главная идея:

Пользователь вводит запрос один раз, приложение ищет треки сразу по нескольким разрешённым источникам, объединяет результаты, показывает качество и доступность загрузки, а затем сохраняет музыку в локальную библиотеку.

1. Важное ограничение по источникам

Для каждого сервиса нужно разделять:

1. поиск;
2. прослушивание;
3. загрузку;
4. сохранение метаданных.

У SoundCloud, VK и других платформ загрузка возможна не для любого трека. Она должна работать только если:

- источник официально разрешает скачивание;
- у пользователя есть необходимые права;
- трек опубликован автором с включённой загрузкой;
- используется официальный API или разрешённый способ доступа.

У Hitmos и похожих каталогов, скорее всего, нет стабильного публичного API. Автоматический парсинг может нарушать правила сайта, ломаться после изменений интерфейса и создавать юридические проблемы. Поэтому я бы не закладывался на «обход» ограничений. Для таких источников нужен отдельный адаптер только после проверки правил использования и технической доступности.

2. Рекомендуемый стек

Вариант, который я бы выбрал:

- Flutter — интерфейс Android, Windows и Linux;
- Dart — бизнес-логика приложения;
- Rust — при необходимости для аудиоядра, быстрых загрузок и работы с файлами;
- SQLite — локальная база библиотеки;
- FFmpeg — только для разрешённой обработки файлов;
- официальные OAuth API — авторизация в сервисах;
- облачный поисковый шлюз — только если конкретные API требуют скрытия ключей.

Flutter хорошо подходит для:

- Android;
- Windows;
- Linux;
- единой дизайн-системы;
- адаптивного интерфейса;
- фоновых операций и уведомлений.

Альтернатива — Kotlin Multiplatform + Compose Multiplatform. Она особенно хороша для Android и Windows, но Linux-часть и мультимедийная экосистема могут потребовать больше ручной работы.

3. Архитектура

Flutter UI (Android / Windows / Linux)
        |
Application Core (Search, Player, Library, UX)
        |-------------------|
Providers                  Local Storage
SoundCloud                 SQLite
VK                         Files
Bandcamp                   Metadata
Jamendo                    Playlists

Каждый источник реализуется через единый интерфейс:

MusicProvider
├── search(query, filters)
├── getTrack(id)
├── getStreamUrl(track)
├── getDownloadOptions(track)
├── authenticate()
└── getUserLibrary()

Тогда добавление нового сервиса не потребует переписывать плеер и библиотеку.

4. Какие источники стоит добавить

SoundCloud

Подходит для поиска, прослушивания, авторских релизов и загрузки треков, для которых автор разрешил download. Потребуется OAuth и аккуратное соблюдение лимитов API.

VK

Подходит как интеграция с пользовательской медиатекой, если доступ разрешён официальными механизмами. Не стоит проектировать приложение вокруг скрытых или неофициальных методов получения аудио.

Bandcamp

Очень хороший источник для легальных покупок и загрузок: качественные файлы, FLAC/MP3, покупки пользователя, независимые исполнители. Можно начать с импорта купленных релизов и локальных файлов.

Jamendo

Хороший вариант для музыки с открытыми лицензиями и легальной загрузки.

Internet Archive

Подходит для public domain, архивных записей, live-концертов и Creative Commons-контента.

Audius или аналогичные открытые платформы

Можно рассмотреть позже, если будет стабильный API и понятные правила загрузки.

YouTube

Я бы не делал его основным источником загрузки. Можно добавить поиск ссылок или официальное воспроизведение, но конвертация произвольных роликов в MP3 часто противоречит правилам платформы и создаёт лишние риски.

5. Поиск

Поиск должен быть не просто списком ответов от API.

Единая модель результата:

Track
├── id
├── provider
├── title
├── artists
├── album
├── artwork
├── duration
├── releaseDate
├── genre
├── explicit
├── streamAvailability
├── downloadAvailability
├── qualityOptions
└── sourceUrl

Фильтры:

- исполнитель;
- альбом;
- жанр;
- длительность;
- качество;
- источник;
- доступность загрузки;
- лицензия;
- lossless/MP3;
- explicit content;
- дата публикации.

Объединение результатов

Один и тот же трек может встретиться в нескольких источниках. Нужно нормализовать названия, сравнивать исполнителя, альбом и длительность, объединять дубликаты, выбирать лучший источник и показывать альтернативные варианты.

Пример:

Daft Punk — Get Lucky

SoundCloud       128 kbps
VK               доступно в библиотеке
Bandcamp         FLAC
Локальный файл   MP3 320 kbps

6. Загрузка

Загрузка должна быть отдельным менеджером задач.

Возможности:

- очередь загрузок;
- пауза и продолжение;
- повтор после ошибки;
- ограничение количества параллельных задач;
- работа в фоне;
- Wi-Fi only на Android;
- выбор папки;
- автоматическое добавление в библиотеку;
- проверка свободного места;
- контроль контрольной суммы;
- сохранение обложки и тегов.

Форматы на первом этапе:

- MP3;
- M4A;
- FLAC;
- OGG;
- WAV.

Не нужно без необходимости конвертировать всё в MP3. Если источник даёт FLAC, лучше сохранить оригинал, а пользователь сможет выбрать формат для офлайн-копии позже.

Структура файлов:

Music/
└── Artist/
    └── Album/
        ├── 01 - Track.flac
        ├── cover.jpg
        └── metadata.json

Пользователь должен иметь возможность выбрать шаблон:

{artist}/{album}/{track_number} - {title}

7. Локальная библиотека

Приложение должно работать local-first:

- музыка доступна без аккаунта;
- база хранится локально;
- локальные файлы индексируются;
- изменения не требуют интернета;
- источники подключаются дополнительно.

База данных:

artists
albums
tracks
files
playlists
playlist_tracks
downloads
providers
playback_history
favorites
settings

Нужно поддержать сканирование папок, импорт существующей музыки, исправление тегов, сортировку, избранное, историю, пользовательские плейлисты, умные плейлисты и поиск по локальной библиотеке.

9. Авторизация

Лучше использовать OAuth 2.0 + PKCE:

Пользователь → официальный сервис → разрешение доступа
             → callback приложения
             → зашифрованный локальный токен

Токены нужно хранить:

- Android — Keystore;
- Windows — Credential Manager/DPAPI;
- Linux — Secret Service или зашифрованное локальное хранилище.

Не стоит отправлять логины и пароли пользователей на собственный сервер.

10. Нужен ли сервер

Для первого релиза можно сделать приложение максимально автономным.

Сервер понадобится, если нужны единый поиск по API с секретными ключами, синхронизация плейлистов, аккаунт пользователя, синхронизация прогресса, проксирование потоков, каталог лицензированного контента или аналитика ошибок интеграций.

Предлагаемая схема:

Приложение
├── локальный поиск по библиотеке
├── официальные API напрямую
└── собственный API только для сервисов,
    где нельзя безопасно хранить ключи в клиенте

Сервер не должен быть универсальным прокси для скачивания защищённого контента.

- Избранное;

Экран поиска

Каждый результат показывает обложку, название, исполнителя, длительность, источник, доступное качество, кнопки «Слушать» и «Скачать», а также меню дополнительных вариантов.

Важно не прятать источник и условия доступности. Пользователь должен сразу понимать, откуда взялся файл и почему определённая кнопка недоступна.

13. Что я бы не делал в первой версии

- универсальный обход ограничений сайтов;
- массовое скачивание всего подряд;
- обязательную регистрацию;
- сложную социальную сеть;
- собственную музыкальную подписку;

- агрессивный web scraping;

14. Итоговая концепция

Рабочее название можно построить вокруг таких принципов:

- локальная библиотека прежде всего;
- единый поиск по подключаемым источникам;
- загрузка только разрешённого контента;
- прозрачный источник и качество каждого трека;
- одинаковое поведение на Android, Windows и Linux;
- провайдерная архитектура, позволяющая добавлять новые сервисы без переделки приложения.

Оптимальный первый набор источников: SoundCloud + Jamendo + Internet Archive + локальные файлы. VK можно добавлять после проверки актуального официального API, а Hitmos — только при наличии разрешённого и устойчивого способа интеграции.
